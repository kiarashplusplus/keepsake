# Keepsake — Identity Model vs. Minors' Laws (Research Findings)

## Verdict

Under Texas's SCOPE Act, applicability turns on a **conjunctive** three-prong test in Bus. & Com. Code §509.002(a): a digital service is covered only if it (1) lets users "socially interact" with other users, (2) lets a user "create a public or semi-public profile for purposes of signing into and using the digital service," AND (3) lets users create/post content viewable by others [search snippet only — statute fetch blocked, see caveat below]. Keepsake's owner row (bearer-token hash + email, never displayed) is not a "profile" in any ordinary sense — nothing about the giver is public or semi-public; the dashboard is private, sign-in-only infrastructure, not an identity surface. Listings are public *content*, not profiles. Prong 3 is plainly met; prong 2 is the weak link for the state, and prong 1 (a one-time note + off-platform contact reveal) is a stretch to call "social interaction on the digital service." If prong 2 genuinely fails, the whole chapter arguably doesn't reach Keepsake — but no court or AG guidance was found construing "profile" this narrowly for a fact pattern like Keepsake's, so this is reasoned inference, not confirmed law. Other states diverge sharply: Maryland's Kids Code and California's AADC gate coverage on revenue/data-volume or "likely to be accessed by children," not on accounts at all — Keepsake's sole-proprietor, near-zero-revenue profile likely falls under Maryland's exemption thresholds, but that's a business-size question, not an identity-model one. An age affirmation at give or confirm steps does not change any of this: none of these statutes' triggers depend on whether you *asked* age — they depend on architecture (profile/social-interact/content) or provider size/reach. What an affirmation *does* do is support a COPPA-style "no actual knowledge" posture (per FTC guidance) — until contradicted. A college pilot recruiting known 17-year-old first-years destroys that posture by design: it manufactures actual/constructive knowledge that minors are using the service, which is what matters for "known minor" and "likely accessed by children" tests, independent of whether an affirmation checkbox exists.

## Findings — items 3–5

- **Craigslist**: TOU requires users be "of sufficient age and capacity to use CL" — no explicit "18" figure found in the clause fetched; no separate minor-attestation checkbox identified. [Craigslist Terms](https://www.craigslist.org/about/terms.of.use) [verified by fetch]
- **Nextdoor**: minimum age reportedly 13 in the US but 18 in the UK, with DOB collection; a jurisdiction-dependent age line, not a uniform 18+ gate. [search snippet only]
- **Freecycle/Trash Nothing/Olio/Buy Nothing**: no verifiable terms-of-service age clauses found; only app-store "13+" content ratings turned up, which are not legal age-of-use attestations. Flag as **not found**.
- **FTC/COPPA framework**: a "neutral" age screen (asking DOB or "how old are you," not "are you 18+?" or a default-checked box) preserves an operator's "no actual knowledge" position; a screen that defaults to an adult answer or otherwise "encourages falsification" does not. Actual knowledge attaches the moment the operator receives *any* information — DOB, grade level, an unprompted statement — indicating a user is a minor, whether or not age was ever directly asked. [FTC COPPA FAQs](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions) [search snippet only]
- **Canada — PIPEDA/OPC**: under-13 generally cannot give meaningful consent (parent/guardian required); 13–17-year-olds can consent but the process must be "adapted to the child's level of maturity" (plain language, layered notices) — a bare 18+/13+ affirmation checkbox is not itself the standard; OPC is separately developing a children's privacy code (2025 consultation). [OPC guidance](https://www.priv.gc.ca/en/privacy-topics/business-privacy/bus_kids/02_05_d_62_tips/) [search snippet only]
- **Quebec Law 25**: age of consent for personal-information collection is **14** — a verified-email giver identity likely needs no parental consent for a 17-year-old in Quebec, since 14+ can consent themselves; consent requests must be presented as a standalone prompt, not buried in a privacy policy. [search snippet only]
- **Requester side**: a requester supplies only an email, confirmed once, with a per-address daily cap and per-listing duplicate check — there is no persistent record to attach a "known minor" flag to beyond the single confirmed request. A `.edu` domain alone is weak evidence of age (grad students, staff); an unsolicited "I'm a freshman" note is stronger circumstantial actual-knowledge evidence under a COPPA-style framework, but no case was found applying this precisely to a marketplace-note context. **Not found / lawyer must confirm.** Because requesters have no account, the "content removal only, no ban" design already sidesteps most known-minor *account* duties (default privacy settings, parental dashboards, notification-time limits) that several statutes impose — there is no account object for those duties to attach to.
